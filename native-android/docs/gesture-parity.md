# Dart / Kotlin behavior parity

The original Flutter production implementation is retained. `test/native_parity_baseline_test.dart` constructs deterministic sequences and generates `parity-fixtures/gesture-goldens.json` only when GENERATE_GOLDENS=true. In normal tests it replays and compares outputs against the saved Dart baseline; expectations are not generated by Kotlin or updated to hide failures.

There are 39 cases and418 landmark samples. Each valid hand sample has all 21 indexed normalized x/y and finite z values. Fixtures include source config, explicit timestampMs, tracking-loss markers, raw classifications, detector phases/ownership, candidate/cooldown/rearm behavior, suppression, motion values, discrete event timestamps/directions and scroll mapping. Invalid samples are rejected at the hand model boundary and recorded as invalid evidence rather than quietly normalized by a detector. Each detector/config can be replayed without a camera or emulator.

Covered cases include stationary/slow up/down, fast flick up/down, short fast motion, sample gaps/discontinuity, tracking loss/reacquisition, duplicate/decreasing/irregular timestamps, reversal/cooldown/rearm, EMA/calibration/confirmation, pose up/down, held pose, neutral release, direct direction change, degenerate/nonfinite/out-of-range landmarks, boundaries and alternate configuration. Extended pure-domain tests validate the isolated CONTINUOUS/FLICK modes alongside HYBRID (old combined) and POSE (old poseOnly). Saved parity cases retain `tapGesturesEnabled=false`. The native app enables the intentional [tap extension](tap-gestures.md): open hand sends one pause tap per presentation, and thumbs-up double taps. Native rearming uses only the configurable delay followed by fresh confirmation; held pointing/thumbs-up can repeat, while a held open hand cannot.

## Run

From repository root:

```powershell
flutter test test/native_parity_baseline_test.dart --reporter expanded
```

From native-android:

```powershell
.\gradlew.bat :gesture:test :app:testDebugUnitTest
```

Deliberate baseline regeneration, only after reviewing an intentional Dart behavior change:

```powershell
flutter test test/native_parity_baseline_test.dart --dart-define=GENERATE_GOLDENS=true --reporter expanded
```

Discrete events, directions, timestamps, phase transitions and suppression compare exactly; floating intermediate outputs use absolute tolerance 1e-9. `GoldenParityTest` covers 39 separate cases; eight `GestureSafetyTest` checks add model/mode/candidate safety. `ScrollGoldenParityTest` independently reads the same saved39 cases/418 samples, exercises native ScrollVelocityMapper and ScrollActionCoordinator, and validates event/action/inversion mapping. JVM recognition tests do not require Android.

## Intentional platform differences

- Camera analyzer callback-arrival elapsed timestamps replace Dart camera callback Stopwatch elapsed timestamps; both timestamp acquisition arrival, not sensor exposure or inference completion. The mapping/freshness test separately checks these clocks. No velocity is derived from configured FPS.
- Camera orientation now follows the active default display rather than locking portrait-up; source pixels rotate upright first. All four rotations have synthetic pixel tests. Existing normalized x mirroring and handedness conventions remain unchanged.
- Flutter ListView scroll execution becomes Android touch swipe dispatch. Continuous detector/sensitivity/mapping defaults are retained, but 100ms bounded strokes approximate proportional movement. Touch slop and target content behavior need physical validation. Page and fast-scroll actions map to full or capped configured touch distance.
- Native starts/resumes explicitly from the Activity and releases camera when paused/screen locked; it does not inherit Flutter's automatic foreground resumption.
- Runtime validation rejects malformed/nonfinite settings at boundaries. Original confidence/21landmark/detector checks remain in the port.
- Native HYBRID/POSE add open-hand single tap and thumbs-up double tap. Timed rearm replaces pose-based release in the native app; the delay is configurable in Settings. Pointing/thumbs-up may repeat after the delay and fresh confirmation; open hand taps once per presentation. `TapGestureTest` tests this extension separately; the saved Dart fixture inputs/expectations and Flutter source are unchanged.

Passing golden fixtures proves behavior on those explicit landmark inputs. It does not establish camera accuracy, arbitrary-hand generalization, feed compatibility, performance gains or all possible lifecycle interleavings. See the migration report for actual executed results and the device guide for remaining trials.
