# Gesture behavior parity

`gesture-goldens.json` contains 39 deterministic cases and 418 samples generated by the existing Dart gesture pipeline. The fixtures retain all 21 indexed landmarks, millisecond sample times, missing-hand markers, all recognition defaults and overrides, configuration changes, and the expected output after every sample. Invalid landmarks are checked at the model boundary and classified as unknown without entering the coordinator.

From the repository root, verify the preserved Dart implementation:

```powershell
flutter test test/native_parity_baseline_test.dart --reporter expanded
```

From `native-android`, compare the Kotlin implementation:

```powershell
.\gradlew.bat :gesture:test
```

The Kotlin suite compares events, directions, event counts and timestamps, pose phases, confirmation progress, cooldown remaining, flick ownership, suppression, and all motion outputs. Discrete outputs and timestamps are exact. Floating-point values use an absolute tolerance of `1e-9` to allow insignificant differences in Dart/JVM arithmetic and trigonometry. Kotlin parity passed without changing any Dart-generated expectation. The scrolling tests consume the same fixture outputs to verify the production action mapping and velocity mapper separately.

The cases include stationary/jitter input, both slow movement directions, both flick directions, insufficient flick duration, discontinuity, tracking loss and reacquisition, duplicate/reversed/negative timestamps, irregular intervals, direction reversal, cooldown and rearm boundaries, EMA tuning, both pointing directions, sustained hold, explicit neutral release, direct pointing direction switching, invalid landmarks, configuration replacement, pose gap and loss, flick ownership, pose hysteresis, and inversion.

The native default `OPEN_HAND` preserves one-shot pointing: a held pose cannot repeat, and neither direction switching nor temporary tracking loss releases its latch. `STABLE_POSE` is an explicit compatibility setting covered by its own fixture; it can repeat a held pose after its dwell and another confirmation. Kotlin's added `CONTINUOUS` and `FLICK` isolated modes have separate deterministic unit tests; Dart's `combined` and `poseOnly` modes correspond to native `HYBRID` and `POSE` respectively.

Input times are milliseconds, as used by native MediaPipe. The baseline's `Duration` values are derived from those exact times; sub-millisecond caller input is outside this fixture contract. Recognition uses the inference sample timestamp, never test execution time or callback arrival time.

To intentionally regenerate after reviewing a confirmed Dart behavior change:

```powershell
flutter test test/native_parity_baseline_test.dart --dart-define=GENERATE_GOLDENS=true --reporter expanded
```

Do not regenerate to resolve a Kotlin mismatch. Review and document the source behavior change first. Ordinary verification never rewrites the baseline.
